| 0.8.0   | 2026-08-04   | **Breaking.** Centralized configuration: one schema (`chesssnake/config.py`) is the single source of truth for every setting, resolved from four layers — CLI flag > environment variable > TOML config file > default — with environment variable names derived mechanically from the schema (`[api] port` ⇄ `CHESSSNAKE__API__PORT`). Adds `chesssnake config show`, which reports the effective value *and the source layer* of every setting, with secrets redacted. Authentication is now explicit (`api.require_auth`) and fails at startup if enabled without a key. The server becomes an app factory (`create_app(settings)`), so the CLI no longer signals it through `os.environ`. **Migration:** every environment variable is renamed — `CHESSDB_*` collapse into a single `CHESSSNAKE__DATABASE__URL` DSN, `CHESSSNAKE_INIT_DB` → `CHESSSNAKE__DATABASE__INIT_SCHEMA`, `CHESSSNAKE_API_KEY` → `CHESSSNAKE__API__API_KEY` (**and now requires `CHESSSNAKE__API__REQUIRE_AUTH=1`, or auth stays off**), `CHESSSNAKE_API_URL` → `CHESSSNAKE__CLIENT__API_URL`. Python 3.10 is dropped (3.11+ for stdlib `tomllib`). Also fixes `chesssnake[client]` failing without psycopg2 installed, repairs the never-working `create_database` path, and returns a proper `{error_type, detail}` envelope on 401 | Gabe Becker | Released |

| 0.9.0   | 2026-08-04   | **Breaking.** Add SQLite support by migrating the database layer to SQLAlchemy Core. The backend is now selected by the `database.url` scheme: `sqlite:///chess.db` or `postgresql://…`. The fourteen query functions are backend-agnostic Core expressions in the new `db/operations.py`, built on a single `MetaData` schema (`db/schema.py`) that replaces the hand-written `data/init.sql`; only genuine dialect differences remain, in `db/postgres.py` and `db/sqlite.py`. SQLite is configured for concurrent use (WAL, `busy_timeout`, and `BEGIN IMMEDIATE` for read-modify-writes, since it has no row locks and SQLAlchemy silently compiles `FOR UPDATE` away there). **Migration:** (1) `pip install chesssnake[api]` no longer installs psycopg2 — PostgreSQL users must install `chesssnake[api,postgres]`; (2) libpq keyword connection strings (`dbname='…' user='…'`) are no longer accepted, only URLs; (3) `db/sql.py` is gone and `db_init` changed signature. Existing PostgreSQL databases need **no migration** — the schema is byte-compatible, proven by a test that builds both and compares reflections. Also: `challenge()` is now atomic (it was four separate transactions), `apply_game_change` is verified serialized by a concurrency test on both backends, and the `UpdatedAt` PL/pgSQL trigger is replaced by SQLAlchemy `onupdate` (existing databases keep their harmless trigger). Engine fix: checkmate is now defined as "in check with no legal move" rather than a separate hand-rolled analysis, which mis-reported scholar's mate (`1. e4 e5 2. Qh5 Nc6 3. Bc4 Nf6 4. Qxf7`) as check — the old code counted the king as able to capture the checking queen even though the bishop on c4 defended it. Pinned pieces are now correctly excluded from both checkmate and stalemate detection | Gabe Becker | Latest   |
